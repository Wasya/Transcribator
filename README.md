# Transcribator

**Transcribator** — небольшой проект для работы с [Deepgram API](https://developers.deepgram.com/): распознавание речи (Speech-to-Text) с помощью Python SDK.

## Структура проекта

- `StartDG.py` — пример транскрибации аудио по URL с помощью `DeepgramClient` (модель `nova-3`, язык `en`).
- `ListenSteam.py` — потоковая (streaming) транскрибация живого аудиопотока (интернет-радио) в реальном времени, с сохранением распознанного текста в файл.
- `TeamsTranscribe.py` — GUI-приложение для расшифровки звонков (Microsoft Teams и подобных) в реальном времени: отдельные потоки для микрофона и системного звука, разделение по говорящим (diarization) и экспорт транскрипта. Движок распознавания выбирается в окне: Deepgram (облако) или WhisperX (локально). Точка входа; вся логика — в пакете `teams_transcribe/`.

## Требования

- Windows 10/11 (для `TeamsTranscribe.py`: захват системного звука через WASAPI loopback, `PyAudioWPatch`)
- Python 3.10+ (проверено на 3.12)
- Распознавание — **на выбор**:
  - **Deepgram** (облако): нужен платный/триальный API-ключ;
  - **WhisperX** (локально, бесплатно): желательна видеокарта NVIDIA (проверено на сценарии RTX 4060), работает и на CPU, но медленнее; для разбора участников по голосам нужен бесплатный аккаунт Hugging Face (см. раздел «WhisperX» ниже).

## Установка

Ниже — полная пошаговая инструкция. Шаги 1–3 нужны всегда, шаг 4 — только для локального WhisperX.

### 1. Виртуальное окружение

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 2. Базовые зависимости (Deepgram + GUI)

```powershell
pip install -r requirements.txt
```

### 3. Файл `.env`

Скопируйте `.env.example` в `.env` и заполните нужное:

```
DEEPGRAM_API_KEY=ваш_ключ     # только для движка Deepgram
HF_TOKEN=ваш_токен_hugging_face   # только для разбора по голосам в WhisperX
```

Если используете только WhisperX — `DEEPGRAM_API_KEY` можно не задавать, в приложении тогда по умолчанию выбирается WhisperX.

### 4. Локальный движок WhisperX (необязательно)

**4.1. Драйвер NVIDIA.** Обновите драйвер видеокарты и проверьте, что в PowerShell работает `nvidia-smi`. Отдельно ставить CUDA Toolkit **не нужно** — нужные библиотеки CUDA/cuDNN входят в сборку PyTorch.

**4.2. PyTorch.** Ставьте **до** WhisperX, иначе pip поставит CPU-версию:

- видеокарта NVIDIA (CUDA 12.6):

  ```powershell
  pip install torch==2.8.0 torchaudio==2.8.0 --index-url https://download.pytorch.org/whl/cu126
  ```

- только CPU (медленнее, нужна модель `small`):

  ```powershell
  pip install torch==2.8.0 torchaudio==2.8.0
  ```

**4.3. WhisperX:**

```powershell
pip install -r requirements-whisperx.txt
```

Скачает несколько ГБ (PyTorch, pyannote, faster-whisper).

**4.4. Проверка окружения:**

```powershell
python check_env.py
```

Выведет версии пакетов, доступность CUDA и наличие ключей (сами значения не показываются). Для работы на видеокарте должно быть `CUDA доступна: True`. Результат этой команды удобно прикладывать к описанию проблем.

**4.5. Hugging Face (для разбора по голосам)** — подробности в разделе «WhisperX» ниже.

**4.6. Первый запуск** скачает модели (Whisper `large-v3-turbo` ≈ 1.6 ГБ, модели pyannote — сотни МБ) в кэш Hugging Face; в окне приложения при этом отображается «Загрузка моделей…». Дальше модели берутся из кэша.

**Возможные проблемы:**

- `Could not load library cublas64_12.dll` / `cudnn…` — `pip install nvidia-cublas-cu12 nvidia-cudnn-cu12`.
- Предупреждения `torchcodec is not installed correctly` и про symlinks на Windows — безвредны, работе не мешают.
- `401`/`403` при загрузке моделей pyannote — не приняты условия модели или неверный `HF_TOKEN` (см. ниже).

## Запуск

```powershell
.venv\Scripts\python.exe StartDG.py
```

Скрипт скачает пример аудио по URL и выведет полный ответ API, а затем — только текст транскрипта.

### ListenSteam.py — потоковая транскрибация

```powershell
.venv\Scripts\python.exe ListenSteam.py
.venv\Scripts\python.exe ListenSteam.py --OutFile Session1
```

Скрипт подключается к живому аудиопотоку (интернет-радио) и распознаёт речь в реальном времени через Deepgram Streaming API. В консоль построчно выводятся промежуточные (`[Interim]`) и финальные (`[ FINAL ]`) результаты распознавания, а **финальные** фразы одновременно сохраняются в текстовый файл (по одной фразе на строку). Остановить прослушивание можно через Ctrl+C.

**Имя выходного файла:**

- Без параметра `--OutFile` файл называется:

  ```
  DeepGram[DD-MM-YYYY]_[HH-MM].txt
  ```

  где `[DD-MM-YYYY]_[HH-MM]` — дата и время запуска скрипта, например `DeepGram26-08-2026_11-09.txt`.

- С параметром `--OutFile <имя>` итоговое имя файла формируется так:
  1. Из переданного `<имя>` удаляются все символы, недопустимые в именах файлов Windows (`< > : " / \ | ? *`, а также управляющие символы).
  2. Результат обрезается до 20 символов (лишнее отбрасывается с правого края, т.е. остаются первые 20 символов).
  3. К обрезанной строке конкатенируется `[DD-MM-YYYY]_[HH-MM].txt` (дата и время запуска).

  Например, `--OutFile 'My<>Radio_Session_Name_TooLong'` при запуске 26.08.2026 в 11:09 даст файл `MyRadio_Session_Name26-08-2026_11-09.txt`.

### TeamsTranscribe.py — расшифровка звонков (GUI)

```powershell
.venv\Scripts\python.exe TeamsTranscribe.py
```

GUI-приложение для расшифровки звонков (Microsoft Teams, Google Meet, Zoom и аналогов) в реальном времени. Захватывает **два** аудиопотока одновременно — микрофон и системный звук (WASAPI loopback, т.е. то, что слышно из динамиков: голоса удалённых участников) — и распознаёт их независимо через Deepgram Streaming API (модель `nova-3`). Системный поток распознаётся с разделением по говорящим (diarization): каждый новый голос появляется в списке «Участники» с автоматическим именем, которое можно переименовать прямо во время разговора. Переименование применяется ко всем репликам этого говорящего в итоговом транскрипте (`transcript.txt`/`transcript.json`), даже к уже произнесённым; в окне программы уже показанные строки сохраняют то имя, что было на момент их появления.

В окне приложения задаются:

- **Микрофон** и **Системный звук** — устройства захвата (выбираются из списков, обнаруженных `PyAudioWPatch`);
- **Язык распознавания** — русский, английский, немецкий или мультиязычный (code-switching);
- **Имя сессии** (опционально) — префикс для имени папки с результатами;
- **Сохранять сырое аудио (WAV)** — если отмечено, помимо транскрипта сохраняются и аудиодорожки.

Кнопка **«Начать»** запускает захват и создаёт папку сессии; кнопка **«Стоп»** останавливает захват и записывает итоговые файлы транскрипта; кнопка **«Заглушить микрофон»** временно отключает передачу звука с микрофона в Deepgram (сам захват не останавливается) — повторное нажатие включает микрофон обратно.

**Папка сессии и экспортируемые файлы:**

Папка создаётся в момент нажатия «Начать» рядом со скриптом, её имя формируется так же, как имя файла у `ListenSteam.py` (`--OutFile`): без «Имени сессии» используется `DeepGramMeeting`, при заданном имени оно очищается от недопустимых в Windows символов и обрезается до 20 символов — итоговое имя папки выглядит как:

```
DeepGramMeeting[DD-MM-YYYY]_[HH-MM]/
```

После нажатия «Стоп» в папке сессии появляются:

- `transcript.txt` — реплики всех говорящих (микрофон и участники) в хронологическом порядке, с меткой времени и именем говорящего;
- `transcript.json` — те же данные в структурированном виде (говорящий, источник, таймкод, текст);
- `speakers/<Имя>.txt` — отдельный файл с репликами каждого говорящего (по имени, присвоенному или переименованному в GUI);
- `mic.wav` и `system.wav` — сырые записи микрофона и системного звука, если была включена опция «Сохранять сырое аудио (WAV)».

⚠️ **Перед началом записи приложение показывает уведомление о согласии на запись:** оно расшифровывает весь разговор целиком, включая голоса удалённых участников, поэтому получение согласия участников на запись и соблюдение политики компании/законодательства — ответственность пользователя приложения.

## WhisperX: локальное бесплатное распознавание в `TeamsTranscribe.py`

В выпадающем списке «Движок распознавания» выберите **WhisperX (локально, бесплатно)**. Интернет нужен только для первой загрузки моделей.

**Как это работает.** Распознавание — faster-whisper (ядро WhisperX), разбор по голосам — pyannote. В отличие от Deepgram, Whisper не стриминговый: речь нарезается на реплики по паузам, и каждая реплика распознаётся после паузы — текст появляется с задержкой в 1–5 секунд, без промежуточных (`interim`) результатов. Микрофон всегда подписан «Я»; разбор по голосам применяется к системному звуку (удалённые участники).

**Режимы разбора по голосам** (список «Разбор по голосам»):

| Режим | Что происходит |
|---|---|
| **После «Стоп» (вариант A)** — по умолчанию | Во время звонка все удалённые участники подписаны как «Собеседник 1». После «Стоп» pyannote анализирует запись `system.wav` целиком и расставляет участников по репликам — самый точный вариант. Запись системного звука для этого сохраняется автоматически (и удаляется после обработки, если не отмечено «Сохранять сырое аудио»). Обработка занимает от десятков секунд до нескольких минут, в окне виден статус. |
| **Во время звонка (вариант B)** | Для каждой реплики считается голосовой отпечаток и сопоставляется с уже услышанными голосами: участники появляются в списке сразу, их можно переименовывать на лету. Точность ниже: короткие реплики (< 1,2 с) приписываются предыдущему говорящему, похожие голоса могут сливаться. |
| **B + A** | Участники видны во время звонка (B), а после «Стоп» итоговый транскрипт уточняется вариантом A. Имена, которые вы дали участникам вручную, переносятся на соответствующих участников итогового разбора. |
| **Не разделять** | Все удалённые участники — «Собеседник 1». Токен Hugging Face не нужен. |

**Модели** (список «Модель WhisperX», по умолчанию «Авто»): `small` — для CPU, `medium`, `large-v3-turbo` — рекомендуемая для видеокарты, `large-v3` — максимум качества. «Авто» = `large-v3-turbo` на CUDA и `small` на CPU. Можно закрепить в `.env`: `WHISPER_MODEL`, `WHISPER_DEVICE` (`auto`/`cuda`/`cpu`), `WHISPER_COMPUTE_TYPE`.

### Аккаунт Hugging Face и токен (нужен для разбора по голосам)

Модели pyannote бесплатны, но «закрыты»: чтобы скачать их, нужен аккаунт Hugging Face, принятые условия использования и токен. Делается один раз.

1. Зарегистрируйтесь на <https://huggingface.co/join> и подтвердите e-mail.
2. Откройте страницу модели <https://huggingface.co/pyannote/speaker-diarization-community-1>, заполните короткую форму и нажмите **Agree and access repository**. Если при первом запуске приложение/лог сообщит о доступе (`401`/`403`) к другой модели `pyannote/...` — так же примите условия на её странице.
3. Создайте токен: <https://huggingface.co/settings/tokens> → **Create new token** → тип **Read** → скопируйте значение (показывается один раз).
4. Впишите токен в `.env`: `HF_TOKEN=hf_xxxxxxxx`. Токен — секрет, как и API-ключ Deepgram: `.env` в git не попадает.

Без `HF_TOKEN` приложение предложит продолжить без разбора по голосам.

### Диагностика

Каждая сессия пишет `session.log` в свою папку (параметры запуска без ключей, ошибки со стеком). Вместе с выводом `python check_env.py` этого достаточно, чтобы описать проблему.

### Тесты

```powershell
python -m unittest discover -s tests
```

Покрывают нарезку речи на реплики, ресемплинг, кластеризацию голосов и перенос разметки после diarization (без GPU и моделей).

## Безопасность: API-ключ

Секреты не хранятся в коде — все скрипты загружают их из переменных окружения `DEEPGRAM_API_KEY` и `HF_TOKEN` (через `python-dotenv` и файл `.env`). Файл `.env` добавлен в `.gitignore` и не должен попадать в систему контроля версий.
