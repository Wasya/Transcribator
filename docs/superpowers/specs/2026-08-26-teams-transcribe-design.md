# TeamsTranscribe — дизайн

Дата: 2026-08-26

## Цель

GUI-приложение на Windows, которое во время звонка (MS Teams или любой другой
видеозвонок) в реальном времени транскрибирует разговор через Deepgram
Streaming API, разделяя реплики на "Я" (микрофон) и удалённых участников
(системный звук, разделённых через diarization), с возможностью назвать
каждого распознанного собеседника по имени и выгрузить результат в формате,
удобном для последующего текстового анализа по каждому участнику отдельно.

## Юридическая оговорка

Приложение записывает/расшифровывает весь разговор, включая голоса удалённых
участников через системный звук. Ответственность за получение согласия
участников на запись (и соответствие политике компании/законодательству)
лежит на пользователе. Приложение выводит предупреждение об этом при старте.

## Архитектура

Два независимых потоковых соединения с Deepgram вместо одного multichannel-
потока: замер показал, что микрофон и loopback-устройство на тестовой машине
работают на разных частотах дискретизации (44100 Гц и 48000 Гц
соответственно) — сведение их в один интерливленный multichannel-поток
потребовало бы ресемплинга и было бы подвержено постепенному рассинхрону на
длинных звонках. Два независимых mono-соединения проще и надёжнее; общий
хронологический порядок реплик восстанавливается по времени получения
(абсолютный wall-clock, вычисленный из времени старта соединения + `start`/
`duration` из ответа Deepgram).

### Компоненты

- **`teams_transcribe/naming.py`** — общая с `ListenSteam.py` логика:
  очистка строки от символов, недопустимых в именах файлов/папок Windows,
  обрезка до 20 символов, конкатенация с `[DD-MM-YYYY]_[HH-MM]`.
  `ListenSteam.py` рефакторится на использование этой функции вместо
  дублирования кода.
- **`teams_transcribe/audio_capture.py`** — захват через `PyAudioWPatch`:
  - `MicCapture`: обычный input-стрим с выбранного устройства (mono, родная
    частота устройства).
  - `SystemCapture`: WASAPI loopback с выбранного устройства вывода (родная
    частота устройства, обычно стерео), даунмикс стерео→моно вручную через
    `array` (без numpy/audioop — простой цикл сложения двух каналов, деление
    на 2), чтобы не тащить лишние/устаревающие зависимости.
  - Оба класса пишут PCM16 чанки в свою `queue.Queue`, работают в отдельных
    потоках.
- **`teams_transcribe/deepgram_stream.py`** — обёртка вокруг
  `client.listen.v1.connect(...)`: одно соединение на источник. Для мика —
  `diarize=False` (там всегда один голос). Для системного звука —
  `diarize=True`. Хранит `datetime` старта соединения для перевода
  относительного `start` из ответа Deepgram в абсолютное время.
- **`teams_transcribe/transcript_store.py`** — потокобезопасное (через
  `threading.Lock`) хранилище реплик и реестр имён спикеров:
  - Ключ спикера: `("mic", None)` или `("system", speaker_id)`.
  - Имя по умолчанию: `("mic", None)` → `"Я"`; `("system", N)` → первое
    появление нового `speaker_id` в канале system создаёт запись
    `"Собеседник {порядковый номер}"`.
  - `rename(key, new_name)` — переименование в любой момент.
  - Реплики хранятся с исходным ключом спикера (не с именем), имя
    подставляется при отображении/экспорте — переименование задним числом
    применяется ко всем прошлым репликам этого спикера.
- **`teams_transcribe/exporter.py`** — по команде Stop создаёт папку сессии
  (имя через `naming.py`, по умолчанию префикс `DeepGramMeeting`) и пишет:
  - `transcript.txt` — хронологический диалог, `[HH:MM:SS] Имя: текст`.
  - `transcript.json` — список реплик
    `{speaker_source, speaker_id, speaker_name, timestamp_iso, is_final, text}`.
  - `speakers/<Имя>.txt` — весь текст конкретного участника подряд, для
    отдельного текстового анализа.
  - `mic.wav`, `system.wav` — сырое аудио каждого канала (опционально,
    управляется чекбоксом в GUI).
- **`teams_transcribe/gui.py`** — tkinter-окно:
  - Выпадающие списки: микрофон, устройство вывода (для loopback), язык
    распознавания (`ru` / `en` / `multi`).
  - Поле "Имя сессии" (опционально, влияет на имя папки экспорта).
  - Чекбокс "Сохранять сырое аудио (WAV)".
  - Кнопки: **Начать** / **Стоп**, **Заглушить микрофон** (toggle).
  - Живой транскрипт: `ScrolledText`, только для чтения, обновляется через
    `.after(100, ...)`, читающий очередь событий из потоков захвата/Deepgram
    (tkinter не потокобезопасен — все обновления UI идут из главного потока).
  - Панель спикеров: построчно — обнаруженный спикер + текстовое поле для
    переименования, пополняется на лету по мере появления новых
    `speaker_id` в канале system.
  - При старте, если не найден `DEEPGRAM_API_KEY` в `.env` — messagebox с
    инструкцией, окно не даёт начать запись.
- **`TeamsTranscribe.py`** — точка входа, запускает `gui.py`.

### Поток данных

1. Пользователь выбирает устройства и язык, жмёт **Начать**.
2. Стартуют потоки `MicCapture` и `SystemCapture`, каждый — своё соединение
   Deepgram (через `deepgram_stream.py`).
3. Чанки PCM пересылаются в Deepgram; при активном mute чанк микрофона
   заменяется тишиной (захват не останавливается — так проще, нет риска
   рассинхрона таймингов очереди).
4. Колбэки Deepgram (`Results`) кладут нормализованное событие в общую
   `queue.Queue` для UI и одновременно обновляют `transcript_store`.
5. GUI раз в ~100мс вычитывает очередь, дописывает финальные реплики в
   `ScrolledText`, обновляет "живую" последнюю строку для interim-результатов,
   добавляет новые строки в панель спикеров при появлении новых `speaker_id`.
6. По **Стоп**: остановка потоков захвата, закрытие обоих соединений Deepgram,
   вызов `exporter.py`, messagebox с путём к папке результатов.

### Обработка ошибок

- Нет доступных устройств записи/loopback → messagebox, кнопка "Начать"
  недоступна.
- Ошибка соединения Deepgram (неверный ключ, сеть) → messagebox, автостоп.
- `DEEPGRAM_API_KEY` не найден в `.env` → messagebox с инструкцией при
  запуске.

## Зависимости

Новая зависимость: `PyAudioWPatch` (WASAPI loopback capture, есть готовые
wheels для Windows). `tkinter` — часть стандартной библиoteки Python,
отдельной установки не требует. `numpy`/`audioop` не используются намеренно.

## Тестирование

Полноценный e2e-тест с реальным звонком Teams в этой среде невозможен.
Ручная проверка: реальный микрофон + системный звук (проигрывание
чего-либо через колонки как имитация "остальных участников"), проверка
живого транскрипта, mute, переименования спикеров, экспорта файлов
(txt/json/per-speaker/wav). Юнит-тестов/pytest в проекте нет — не вводится
отдельный фреймворк, только ручная проверка ключевой логики (санитайзинг
имён папок, работа реестра спикеров).

## Вне рамок (не делаем)

- Идентификация говорящих по голосу через ML (voice ID) — только ручное
  именование через GUI.
- Поддержка не-Windows платформ (WASAPI loopback — Windows-специфичная
  возможность).
- Автоматическая суммаризация/анализ текста по участникам — только выгрузка
  данных в удобном для стороннего анализа формате.
